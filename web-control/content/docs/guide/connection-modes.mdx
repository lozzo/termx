## 连接模式

termx 当前有三种运行模式：`local`、`hub`、`both`。

### `local`：只做本地或局域网连接

```bash
termx --listen :8080
```

适合：

- 手机和机器在同一局域网
- 想先体验产品，不依赖 Web 账号与订阅
- 更看重部署简单和本地直连延迟

特点：

- 本机服务会启动本地 HTTP 服务
- 二维码里会包含本地连接信息
- 默认带本地密码认证（除非使用 `--no-auth`）

### `hub`：只做远程 Hub 连接

```bash
termx remote enable --server <control_url>
termx daemon
```

适合：

- 机器没有方便的局域网直连条件
- 你主要依赖外网远程访问
- 想把节点统一注册到控制台

特点：

- 不依赖本地监听入口对外提供服务
- 需要连接密钥
- 需要可用订阅才能在控制台真正使用远程连接能力

### `both`：本地 + Hub 混合模式

```bash
TERMX_REMOTE_LOCAL_WEB_ENABLE=1 termx remote enable --server <control_url>
termx daemon
```

这是最推荐的长期运行模式。

适合：

- 在家/办公室时希望直接走本地网络
- 外出时仍希望通过 Hub 连回机器
- 想让 Android 客户端自动在多条路径里选择更优连接方式

### Hub 接入说明

默认情况下，Hub 模式会自动完成控制面发现和接入。对普通用户来说，不需要额外配置 Hub 地址或控制面参数。

如果你在做内部部署或自建环境，请在对应部署文档里管理这些参数，而不是按公开用户文档手动设置。

### 三种模式怎么选？

| 场景 | 推荐模式 |
|------|----------|
| 只想先体验 | `local` |
| 只关心远程 | `hub` |
| 日常长期使用 | `both` |

### 两个容易忽略的点

1. `hub` 模式下，`--connect-addr` 没有意义，会被忽略。
2. 远程节点通常要经过“注册 + 扫码配对”两个阶段；注册不等于已经完成配对。
