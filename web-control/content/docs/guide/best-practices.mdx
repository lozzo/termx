## 多 Agent 协同最佳实践

如果你已经把 termx 当成“移动指挥台”，最实用的做法通常不是只跑一个 Agent，而是让多个 Agent 在不同 TermX 终端 中各司其职。

### 一个可落地的四角色分工

| Pane | 角色 | 推荐工具 | 典型职责 |
|------|------|----------|----------|
| 0 | 指挥官 | Claude Code | 拆解任务、审查结果、协调冲突 |
| 1 | 后端执行者 | 任何你擅长的编码 Agent | API、数据库、业务逻辑 |
| 2 | 前端执行者 | 任何你擅长的编码 Agent | UI、交互、样式 |
| 3 | 工具/运维助手 | OpenCode 或 shell | Git、构建、测试、日志、发布 |

<Callout type="info">
重点不在于一定要用哪家模型，而在于每个 pane 的职责要稳定，这样你在手机上切换查看时不会混乱。
</Callout>

### 推荐流程

<Steps>
<Step>
### 先规划 pane 布局

把不同角色固定在不同 pane，避免同一 pane 里来回切换上下文。
</Step>

<Step>
### 让“指挥官 Agent”先拆任务

先让一个主 Agent 输出：

- 任务边界
- 各 Agent 的分工
- 需要共享的接口、数据结构或约束

这样你在手机上分发任务时，信息会更统一。
</Step>

<Step>
### 用控制台提前配置 Fn 和片段

把以下内容提前配好：

- 高频确认词：`yes`、`no`
- 常用指令：`/compact`、`/clear`
- 多行模板：测试要求、提交规范、代码审查要求

这样在手机上给多个 Agent 发送相似指令时会快很多。
</Step>

<Step>
### 用路径收藏固定项目入口

为每台节点保存项目根目录、日志目录、部署目录。移动端接入后可以更快切到正确位置，减少输入成本。
</Step>

<Step>
### 把构建和测试留给独立 pane

不要让主 Agent 一边写代码一边跑所有测试。把测试、打包、日志查看留给单独的 pane，手机上排查会更清晰。
</Step>
</Steps>

### 三条非常实用的原则

1. **每个 pane 只做一种角色**：减少上下文污染。
2. **会话命名要稳定**：例如 `api`、`web`、`ops`、`review`，方便手机端快速识别。
3. **长任务都放进 TermX 终端**：这样你离开桌面后也不会中断。

### 什么时候最适合多 Agent？

- 同时推进前后端改动
- 一边修 Bug，一边让另一个 Agent 跑测试和收集日志
- 指挥一个主 Agent 做方案设计，让其他 Agent 并行执行细节

### 什么时候不值得？

- 任务非常小，只改 1 到 2 个文件
- 任务边界很模糊，拆开反而会增加协调成本

这时单 Agent + termx 的移动端跟进体验通常已经足够好。
